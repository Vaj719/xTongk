# تشغيل السيرفر واللوحة

## 1. ارفع الملفات

من مجلد `server/` ارفع إلى جذر الموقع (`public_html`):

```
connect.php
lib.php
keys.json
.htaccess
admin/index.php
```

ثم أنشئ مجلد `data/` بجانب `lib.php` وأعطه صلاحية الكتابة (`755` أو `775`).

## 2. افتح اللوحة

```
https://tongk.wisp.uno/admin/
```

**كلمة السر:** `Haider2008@#77`

- ثلاث محاولات فقط.
- بعد الثالثة: حظر 30 دقيقة لنفس الـIP.
- العداد محفوظ بـ`data/attempts.json`.

## 3. اللوحة

- **إحصائيات:** كل الأكواد، النشط، المنتهي، الموقوف، الأجهزة المربوطة، اللي ينتهي خلال 3 أيام.
- **إضافة كود:** كود يدوي أو توليد تلقائي + أيام + ساعات + دقائق + حد الأجهزة.
- **لكل كود:** حذف، إيقاف/تشغيل، +أيام، تعديل حد الأجهزة، فصل الأجهزة (تصفير الربط).
- **عمود الأجهزة:** `المربوط / الحد`.
- **آخر ظهور:** آخر مرة فتح فيها الجهاز التطبيق.

## 4. التشفير بين التطبيق والسيرفر

كل طلب ورد مشفّرين بـAES-256-GCM على مستوى التطبيق، فوق TLS:

```
التطبيق: JSON → AES-256-GCM (IV عشوائي) → base64 → POST d=<...>
السيرفر: يفك → يفحص → يرد بنفس الطريقة
```

- لا يوجد أي حقل مقروء في الطلب أو الرد — حتى لو فك أحد TLS، يشوف base64 فقط.
- كل رسالة تحمل `t` (وقت الإرسال)؛ السيرفر يرفض أي طلب أقدم من 3 دقائق.
- المفتاح المشترك مخزّن بـ`lib.php` ومشتّت داخل الـAPK — تغييره يوقف النسخ القديمة فوراً.

## 5. تجربة سريعة

من اللوحة أنشئ كوداً، ثم أدخله بالتطبيق. إذا ظهر «Bad request» يعني المفتاح المشترك ما يطابق بين `lib.php` والتطبيق.

## 6. ملاحظات

- `.htaccess` يمنع فتح `keys.json` و`attempts.json` و`lib.php` من المتصفح، ويحمي مجلد `data/`، ويجبر HTTPS.
- **نسخة احتياطية:** نزّل `data/keys.json` بين فترة وفترة — كل مفاتيحك وأجهزتك فيه.
- لتغيير كلمة السر: ولّد hash جديد بـ`hash_pbkdf2` وبدّله في `lib.php`.
